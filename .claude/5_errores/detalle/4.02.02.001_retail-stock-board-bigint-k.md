# 4.02.02.001 · Report Retail — stock-board crash ref «K» (confecciones)

**Código índice:** `4.02.02.001`  
**Módulo:** Report · `/retail` · Segundo módulo Informes  
**Severidad:** **CRÍTICA** (módulo inutilizable)  
**Estado:** ✅ **RESUELTO** — 2026-06-17  
**Etapa relacionada:** Import multi-proveedor 638 · lote CLI-TEST  
**Shibboleth:** 7 años

---

## Síntoma

- Pantalla `/retail` — error rojo: **`invalid input syntax for type bigint: "K"`**
- `/api/retail/stock-board` → 500
- UI caía a **modo demo** (tarjetas #1–#3 hardcoded) aunque lote CLI-TEST existía
- Ranking / filtros / catálogo **no cargaban datos reales**

---

## Causa raíz

1. Lote **CLI-TEST** (~50k filas) mezcla **calzado 654** + **confecciones Kyly 638**
2. Confecciones usan referencia sintética **`K`** (`linea_referencia` par L+K) — ver `confecciones_fk.py` · `st_vt_rc_import.py`
3. SQL `RETAIL_STAGING_SELECT_SQL` hacía `referencia_codigo_proveedor::bigint` en JOIN **sin cast seguro**
4. Postgres evalúa el cast aunque la ref no sea numérica → **aborta toda la query**

**No era:** CSS · filtros UI · ranking · imágenes Storage.

---

## Solución (hotfix 2026-06-17)

### A · SQL seguro + FK-first (obligatorio)

**Archivo:** `report/src/lib/retail/staging-row.ts`

- JOIN `linea` / `referencia` por **`linea_id` / `referencia_id`** cuando existen
- Cast numérico solo con `CASE WHEN ~ '^[0-9]+$' THEN …::bigint END`
- Ref **`K`** ya no rompe la lectura del lote

### B · Filtro predeterminado tipo_v2 = Calzados (producto)

**Archivos:** `report/src/lib/retail/retail-filters.ts` · `RetailStockClient.tsx` · APIs retail

- **`DEFAULT_RETAIL_FILTERS`** → `tipoV2Ids: [1]` (Calzados 654)
- Sin param URL → solo calzado; excluye confecciones del catálogo por defecto
- `COALESCE(tipo_v2_id, 1)` en filtros SQL y memoria
- Confecciones visibles solo si el usuario elige **Producto → Confecciones (2)** en dropdown

**Archivo auxiliar:** `report/src/lib/retail/query-filtros.ts` — mismo patrón cast seguro en JOIN línea.
