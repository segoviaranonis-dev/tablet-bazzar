# 4.01.06.001 — RIMEC Web · FI mezcla CASOS distintos (violación R-FI-1)

**App:** RIMEC Web  
**Ruta:** `/carrito` · confirmar pedido  
**Fecha:** 2026-07-22  
**Estado:** ✅ **DEPLOY PROD 2026-07-22** · commit `30a23b8` · Vercel Ready · https://rimec-web.vercel.app  
**Protocolo:** R-FI-1 · 1 FI = 1 cliente × 1 marca × **1 caso**  
**CHUSAR:** [CHUSAR_HOTFIX_FI_CASOS_DISTINTOS_20260722.md](../../2_modulos/2.2_rimec_web/CHUSAR_HOTFIX_FI_CASOS_DISTINTOS_20260722.md)

## Síntoma

Al confirmar el carrito, una sola factura interna juntaba artículos de **CASOS distintos** (violación grave de protocolo de facturación).

## Causa

`fragmentarCarrito` (`store/sesionVenta.ts`) agrupaba solo por **nombre string** `item.caso`:

```ts
const caso = (item.caso && String(item.caso).trim()) || 'Sin caso'
```

Si `descp_caso` / `caso_snapshot` venía vacío pero `caso_id` era distinto, todos caían en **«Sin caso»** → una FI mezclada. El RPC `confirmar_pedido_web` no re-splitea: inserta una FI por celda del payload.

## Fix

1. `lib/facturaCasoClave.ts` — clave `id:{caso_id}` manda; nombre solo si no hay id.
2. `fragmentarCarrito` usa esa clave + etiqueta `Caso #id` si falta nombre.
3. Matching de descuentos FI también por `caso_id`.
4. Espejo en `scripts/confirmar_carrito_vendedor.mjs`.

## Smoke

```bash
npx tsx rimec-web/scripts/_smoke_fi_caso_split.ts
```

→ `PASS_FI_CASO_SPLIT` · 3 FI para caso_id 101/202/303 aunque el nombre esté vacío.

## Residual

- Facturas ya emitidas en prod con mezcla: **no se reescriben** automáticamente (auditoría manual / OT).
- RPC sigue resolviendo `caso_id` por nombre de biblioteca cuando hay texto; con etiqueta `Caso #id` el payload manda `caso_id` numérico.
