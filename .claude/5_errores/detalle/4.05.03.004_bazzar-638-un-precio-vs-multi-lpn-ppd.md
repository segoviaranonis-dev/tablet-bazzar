**Código:** `4.05.03.004`  
**App:** Bazzar Web · catálogo Confecciones `:3002` / prod  
**Ruta:** `/catalogo?ramo_tipo=CONFECCIONES`  
**Detectado:** 2026-08-10 · Director (captura + mapa 1000034 / 1000031)  
**Estado:** 🔴 **ABIERTO** — UI bucket montada · **dato/precio×talle NO paridad RIMEC**  
**Severidad:** 🔴 **ALTA** — cliente compra con precio aplastado; viola ley holding **638 = mismas reglas en todas las apps**  
**Clase:** Error **inocente** por **falso PASS** de smoke + falta de auditoría **precio×talle vs PPD** (no por malicia)

## Síntoma

- Tarjeta Kyly muestra **un** «Gs. X /prenda» + chips de talle.
- En PPD el mismo L+R+color tiene **2+ LPN** (ej. 65.000 vs 79.500).
- RIMEC Web PE agrupa sub-tarjetas por precio; Bazzar **no**.

| Capa | Resultado |
|------|-----------|
| PPD | LPN **65000** (T1–T3) · **79500** (T4/T6/T8) → **2 precios** |
| `v_stock_web` ALM | Solo T1+T2 · un `precio_web` **98000** (65k+50%) |
| `agruparTallasPorPrecio638` | **1 bucket** |

`1000031` / `11`: PPD **3** LPN · ALM 1 precio.

---

## Causa raíz

1. Helper UI `agruparTallasPorPrecio638` **sí** está (doc **2.5.1.23** lo dio por cerrado).
2. Enrich `loadPpdAmTalleIndex` / `remapTallas638DesdePpd` trae **etiquetas** `am_talle`, **no** `precio_lpn` por talle.
3. ALM publica **un** `precio_web` por combinación viva → el agrupador no puede inventar buckets.
4. Smoke 2026-08-07 validó «bucket + carrito 54000» en un SKU de **un** LPN — **no** cruzó PPD multi-LPN.

**No es** “el módulo no existe”. Es **paridad de ley 638 a medias** + auditoría débil.

---

## Ley violada (holding)

| Canon | Exigencia |
|-------|-----------|
| `3.02.00.638` | Grada abierta · 1 talle = 1 SKU · precio por talle |
| `2.2.1.0.11` / `2.2.1.0.12` | RIMEC: `agruparTallasPorPrecio` |
| `2.5.1.23` | Bazzar debía ser **paridad** rimec-web |
| Norte `5.01.00.026` | Capa **Manos** no miente el precio de venta |

**638 debe tener siempre las mismas reglas** en Report · RIMEC Web · Bazzar Web. Un falso “implementado” en una app es deuda contra el holding.
