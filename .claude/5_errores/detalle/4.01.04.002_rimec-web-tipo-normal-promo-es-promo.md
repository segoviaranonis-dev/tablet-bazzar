# 4.01.04.002 — RIMEC Web PE · Tipo Normal deja pasar línea promocional (es_promo)

**App:** RIMEC Web  
**Ruta:** `/` · Pronta entrega · filtro Tipo **Normal**  
**Fecha:** 2026-07-20  
**Estado:** ✅ Corregido + deploy prod (orden Director 2026-07-20)  
**Protocolo:** [CHUSAR_FILTRO_TIPO_HERMANOS_SIAMESES_20260720.md](../../2_modulos/2.2_rimec_web/CHUSAR_FILTRO_TIPO_HERMANOS_SIAMESES_20260720.md)

---

## Síntoma

Filtrar stock **Pronta entrega** con Tipo **Normal** (carpeta abiertos) mostraba
línea **1395** con badge **PROMO**.

## Causa

`v_stock_pe_rimec` para 1395:

| Campo | Valor |
|-------|--------|
| `descp_caso` | `BR-VZ-MD-ML-MKA-O` (caso Normal) |
| `es_promo` | `true` |
| `cadena_comercial` | `PROMOCIONAL` |

El filtro Tipo tipaba solo por `descp_caso` / BCL. El badge usaba `es_promo`.
Hermanos siameses desalineados: badge ≠ filtro.

## Fix

- `rimec-web/lib/filtros/filtro-tipo-canonico.ts` — `esPromoRow` exclusivo antes de Normal
- `rimec-web/lib/catalogoFilters.ts` — memoria pasa `es_promo`
- `report/src/lib/filtros/filtro-tipo-canonico.ts` — misma ley (AM)

## Smoke

```bash
node rimec-web/scripts/_smoke_tipo_promo_1395.mjs
```

PE + Tipo Normal → **0** tarjetas línea 1395 · Tipo Promo → sí aparecen.
