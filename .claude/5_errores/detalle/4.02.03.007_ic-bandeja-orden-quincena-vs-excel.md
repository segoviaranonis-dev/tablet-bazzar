# 4.02.03.007 · Bandeja IC/Digitación — orden Excel invertido roto por quincena

**Capa:** Report · IC bandeja · Digitación programado  
**Estado:** ✅ **RESUELTO 2026-07-09**  
**Gravedad:** Operativa — orden lote importación Excel  
**Keyword cierre:** Director · **Documenta**

---

## Síntoma

Tras inyección IC PROGRAMADO (373 filas · números `IC-2026-0112`…`0484` con **orden Excel invertido**):

- **Esperado:** primera tarjeta = última fila Excel · **IC-2026-0112** · Gs. **8.824.000** · shop **2400**
- **Observado:** primera tarjeta **IC-2026-0306** · 2da quincena agosto · otro monto

Director confirmó: datos en BD correctos · fallo **visual** en bandeja.

---

## Causa

Queries ordenaban **`quincena_arribo_id ASC` antes que `numero_registro ASC`**.

La numeración invertida del lote ata fila Excel ↔ secuencia IC, pero quincenas distintas (ej. 16 vs 18) reordenaban tarjetas y rompían paridad con el Excel.

| Archivo | Query afectada |
|---------|----------------|
| `report/src/lib/intencion-compra/pendientes-query.ts` | `listIcPendientes` |
| `report/src/lib/digitacion/bandeja-query.ts` | `listIcPendientesDigitacion` |

---

## Fix

```sql
-- Antes (incorrecto para lote Excel invertido)
ORDER BY ic.quincena_arribo_id ASC NULLS LAST, ic.numero_registro ASC

-- Después (canónico lote + paridad Digitación)
ORDER BY ic.numero_registro ASC
```

**Regla:** en import batch con numeración invertida, **`numero_registro ASC`** = última fila Excel primero · fila 3 al final.
