# 4.02.03.002 · Panel Control Compra previa ≠ Estadísticas RIMEC Web

**Capa:** Report · Panel de Control · Alejandro Magno  
**Estado:** ✅ Corregido 2026-07-05  
**Gravedad:** Integridad KPI holding — violación grave  
**Keyword origen:** Director · **Documenta**

## Síntoma

Tarjeta **COMPRA PREVIA · Tránsito** en `/rimec?mundo=panel-control` mostraba totales distintos a **RIMEC Web → Estadísticas** (`/estadisticas`) con mismos PP en tránsito.

Ejemplo observado:
| | Panel (mal) | Web (canónico) |
|---|-------------|----------------|
| Inicial | 53.128 | 33.576 |
| Vendido | 11.912 | 9.288 |
| Saldo | 41.216 | 24.288 |

## Causa

`aggPpPorCategoria(categoria_id=2)`:
- No filtraba `pedido_proveedor.estado_transito = 'EN_TRANSITO'`
- Incluía PP fuera del universo web (cerrados / no tránsito)
- Usaba `GREATEST(pares_vendidos, SUM(venta_transito))` — Web usa solo `pares_vendidos`
- Filtro `linea IS NOT NULL` vs Web `referencia IS NOT NULL`

## Fix

- Nuevo módulo: `report/src/lib/panel-control/compra-previa-estadisticas-web.ts`
- Espejo de `rimec-web/lib/controlStock/fetchControl.ts` + `calcularKpis`
- Doc: `.claude/2_modulos/2.3_report/gestion_compra/CHUSAR_PANEL_CONTROL_COMPRA_PREVIA.md`

## Smoke

1. Web `/estadisticas` — KPIs sin filtros
2. Report panel — tarjeta COMPRA PREVIA **debe coincidir exacto**
