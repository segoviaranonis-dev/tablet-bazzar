# 4.05.03.002 — Bazzar Web · FAIL grada 638 sin am_talle

| Campo | Valor |
|-------|-------|
| App | Bazzar Web |
| Ruta | `/auditoria-local` · catálogo `:3002` |
| Severidad | MEDIA — stock OK pero grada ropa inválida |
| Estado | 🟢 **MITIGADO** 2026-08-02 · auditoría lee PPD `am_talle` · doc **2.5.1.7** v2.4 |
| Código doc | **2.5.1.9** · protocolo **3.02.00.638** |

---

## Síntoma

- Pestaña **Confecciones 638** en auditoría local: `ok_stock=true` · **`ok_grada_638=false`**
- Banner: *PASS stock · FAIL grada 638*
- Catálogo puede mostrar tallas **34–39** en modelos Kyly/Milon
- Badge *Stock OK · Sin am_talle* por modelo

Smoke 2026-08-02: 13 modelos confecciones · 104 prendas · todos FAIL grada.

---

## Causa raíz

Import retail **ALM_WEB** usó **`talla_codigo`** del pilar calzado (654) en filas **`tipo_v2_id=2`** sin poblar:

- `pedido_proveedor_detalle.am_talle`
- `grades_json` estilo Carlos (`{ "P": 3 }`)
- `am_modo_venta = UNIDAD`

El stock cuadra (pares/prendas) pero la **semántica de talle** es calzado, no ropa 638.

---

## Qué NO hacer

| Acción | Por qué |
|--------|---------|
| Tratar 34–39 como talla ropa | Contaminación 654 |
| Usar `ok_stock` como único juicio | Oculta FAIL grada |
| Aplicar `MATRIZ_GRADA_12` | Solo calzado importadora |
| Deploy auditoría a prod | Módulo LOCAL blindado |

---

## Fix correcto

1. Backfill `am_talle` desde `grada` Carlos en PPD/ALM filas proveedor 638.
2. Exponer `am_talle` en `v_stock_web` para confecciones.
3. UI Bazzar: rama 638 → `parseGradaAbierta638` / `esTalle638Canonico`.
4. Validar `:3002/auditoria-local` hasta `ok_grada_638=true`.
