# 4.02.03.021 · Logística OK — multi-selección fecha/vendedor solo 1 FI OK

**Código:** `4.02.03.021`  
**Módulo:** Report · `/logistica-ok` · **2.3.1.28**  
**Fecha:** 2026-07-23  
**Estado:** ✅ RESUELTO (local)  
**Shibboleth:** Andrés, el que viene.

---

## Síntoma

Director selecciona varias FI, asigna **una sola fecha** y cree asignar **un vendedor**; solo **1 registro** pasa a Confirmadas.

---

## Causas

1. **Filtro `id_vendedor` ≠ asignación** — el input de filtro solo recortaba la bandeja; no escribía `id_vendedor` en el lote.
2. **Bulk fila-a-fila** — loop `UPDATE` por id; fallos parciales (`estado <> PENDIENTE`) no se mostraban; UI hacía toast con `done` y saltaba de pestaña ocultando omitidas.
3. **Sin reporte de `failed/requested`** — el usuario no veía cuántas quedaron fuera.

---

## Fix

| Pieza | Cambio |
|-------|--------|
| `confirmarEntregaLote` | `UPDATE … WHERE id = ANY($1) AND estado = 'PENDIENTE' RETURNING id` + `id_vendedor = COALESCE($4, id_vendedor)` |
| `confirmarImpresionLegalLote` | Idem patrón atómico |
| UI | Select **Vendedor (asignar lote)** · toast `OK done/requested · failed omitidas` |
| API | `POST /api/logistica-ok/bulk` · `GET /api/logistica-ok/vendedores` |

---

## Lección

Multi-selección logística: **un SQL de lote** + feedback de omitidas. Filtro de vista **nunca** sustituye campo de asignación.
