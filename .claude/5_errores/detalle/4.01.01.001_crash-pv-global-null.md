## 🔍 CAUSA RAÍZ

### **Origen del bug:**

El error fue **introducido el 2026-06-08** durante la migración FI → PV.

**Commit problemático:** `7f3783d` - "fix(pedidos): Eliminar campos legacy y completar migración PV"

### **¿Qué pasó?**

Durante la simplificación del código, se eliminó una validación crítica:

**CÓDIGO ANTERIOR (funcionaba):**
```typescript
interface FacturaInternaRow {
  pv_global: number | null  // Permitía null
}

function fmtPV(fi: FacturaInternaRow): string {
  // ✅ VALIDACIÓN PRESENTE
  if (fi.pv_global) {
    return `PV${fi.pv_global.toString().padStart(6, '0')}`
  }
  return fi.nro_factura  // Fallback
}
```

**CÓDIGO NUEVO (causó el crash):**
```typescript
interface PreventaRow {
  pv_global: number  // Declarado como required
}

function fmtPV(pv: PreventaRow): string {
  // ❌ SIN VALIDACIÓN
  return `PV${pv.pv_global.toString().padStart(6, '0')}`
}
```

### **El problema:**

1. Se asumió que `pv_global: number` (sin `| null`) protegería en runtime
2. **TypeScript solo valida en compile-time**, NO en runtime
3. La base de datos SÍ puede retornar `pv_global = null` en ciertos casos
4. Cuando llegaba un `null`, el código crasheaba en `.toString()`

---

## ✅ SOLUCIÓN APLICADA

### **Fix implementado:**

Restaurar validación nullish antes de `.toString()`:

```typescript
function fmtPV(pv: Preventa): string {
  // HOTFIX 2026-06-09: Prevenir crash cuando pv_global es null
  if (!pv.pv_global) return 'PV-PENDIENTE'
  return `PV${pv.pv_global.toString().padStart(6, '0')}`
}
```

1. `rimec-web/app/mis-facturas/page.tsx` (línea 56-59)

## 🎯 LECCIONES APRENDIDAS

### **1. TypeScript NO es validación de runtime**
```typescript
// ❌ MAL: Asumir que esto protege en runtime
interface Data {
  field: string  // Sin | null
}

// ✅ BIEN: SIEMPRE validar antes de usar métodos
const texto = data.field ? data.field.toUpperCase() : 'DEFAULT'
const texto = (data.field ?? 'DEFAULT').toUpperCase()
```

### **2. No eliminar validaciones "redundantes" sin confirmar**
Si una validación existe, probablemente está ahí por una razón.

### **3. Al simplificar código, probar en producción**
Los cambios que parecen "safe" pueden tener efectos inesperados.
