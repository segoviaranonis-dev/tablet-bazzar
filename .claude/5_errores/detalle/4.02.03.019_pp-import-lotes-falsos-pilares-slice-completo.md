## Síntoma vs errores hermanos

| Código | Qué parece | Qué pasa en realidad |
|--------|------------|----------------------|
| **4.02.03.017** | Timeout al conectar pool | Deadlock max=1 en TX |
| **4.02.03.018** | 504 al confirmar | Re-preview + pilares en TX larga |
| **4.02.03.019** | 504 «con lotes» | **Lote 1 provisiona TODOS los pilares** del Excel antes de insertar 300 filas |

**Regla:** Si el primer request del loop sigue procesando **N filas completas** de pilares, **los lotes no sirven**.

---

## Causa raíz

En `importProformaProgramadoPhased` · `phase=ppd` · `ppd_offset=0`:

```text
preparePpdImportLookups(pool, pp, detalle COMPLETO, …)
  → provisionPilaresFromProforma(…, TODAS las filas …)
  → populatePpFromProformaBatch(…, slice 300 …)
```

El slice solo acortaba el **INSERT PPD**; la provisión pilares seguía siendo **O(N total)** en el primer request → timeout oficina / proxy lento.

---

## Fix canónico (2026-07-23)

| Pieza | Cambio |
|-------|--------|
| `preparePpdImportLookups` | Recibe **solo el slice** del lote actual |
| `phase=ppd_plan` | Analiza Excel + gate · devuelve SKUs · pares · IC · **N lotes** · offset retoma |
| `PROFORMA_PPD_BATCH_SIZE` | **120** SKUs por request (antes 300) |
| `ProcesoImportacionQueueOverlay` | Cola UI: Inicio → Analizando → Realizando 1/N → **100% exitoso** → ¡Importación exitosa! |
| `PpTabStock.tsx` | Loop `ppd_plan` + `ppd` · reintento 504 por lote · retoma desde `COUNT(ppd)` |
| Retoma | `ppd_offset` desde BD · no borrar PPD parcial |
