## Síntoma

En prod, al usar tab **Importación Stock** del PP:

1. Botón **«2 · Confirmar import programado»** no avanzaba o fallaba tras espera larga.
2. Mismo mensaje al activar **Logística OK → Publicar** en el mismo PP.
3. Error HTTP / overlay: **`timeout exceeded when trying to connect`**.

**Casos operativos:** PP-327, PP-32 (`PP-2026-0023`, proforma `8894/2026`).

---

## Causa raíz

Vercel serverless + `RIMEC_PG_POOL_MAX=1` (canónico post-EMAXCONN): **una sola conexión** por lambda.

Patrón **incorrecto** (autodeadlock):

```
client = pool.connect()   // ocupa la única conexión
BEGIN
  pool.query(...)         // 2ª conexión → espera ~8s → timeout
```

Ocurrencias:

| Función | Consulta paralela durante TX |
|---------|------------------------------|
| `populatePpFromProforma` | `loadPpCasoContext(pool)` dentro de transacción |
| `populatePpFromProforma` | auditoría pilares / `loadIcs` antes de `release` |
| `publicarLogisticaPp` | `getLogisticaPpStats(pool)` antes de `release` |

Los reintentos de `2af40a7` **no** resolvían: el deadlock era determinístico.

---

## Fix (`674b99c`)

**Regla:** prefetch **antes** de `connect()` · trabajo post-TX **después** de `client.release()`.

| Archivo | Cambio |
|---------|--------|
| `proforma-programado-engine.ts` | `casoCtx` / casos evento **antes** TX · audit pilares **después** release |
| `sync-pp.ts` (Logística OK) | `getLogisticaPpStats` **después** release |

---

## Operación (evitar recurrencia)

1. Tab **Importación Stock** primero: preview → confirmar (overlay 1–3 min).
2. **Logística OK / Publicar** solo **después** de FI confirmadas en Admin IC.
3. **No** ejecutar import y logística en paralelo sobre el mismo PP.
