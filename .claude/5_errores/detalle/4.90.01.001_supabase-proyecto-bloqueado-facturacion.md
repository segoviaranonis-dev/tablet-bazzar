# 4.90.01.001 · Supabase — proyecto bloqueado por facturación (DNS caído · holding offline)

**Código:** `4.90.01.001`

**Apps afectadas:** RIMEC Web · Report · Bazzar Web · Tablet (mismo proyecto Supabase)  
**Proyecto:** `extrlcvcgypwazxipvqm` · URL `https://extrlcvcgypwazxipvqm.supabase.co`  
**Detectado:** 2026-08-03 · prod `rimec.com.py` + Report  
**Estado:** ✅ **RESTABLECIDO 2026-08-03** (pago / reactivación por colaborador **Andrés** desde casa) · 🟡 **pendiente endurecer** (alertas, 2FA, backups, owners) — ver § Pendiente  
**Severidad:** Crítica — operación completa del holding sin BD

---

## Síntoma

- RIMEC Web prod: **`TypeError: fetch failed`** · filtros MOLECULA **0** · «Sin opciones».
- API host: DNS **NXDOMAIN** (`extrlcvcgypwazxipvqm.supabase.co` inexistente).
- Pooler `aws-1-sa-east-1.pooler.supabase.com` alcanzable por TCP, pero:
  - `tenant/user postgres.extrlcvcgypwazxipvqm not found` (XX000).
- Login Report: fallaba validación contra `usuario_v2` (BD inalcanzable; síntoma se confundía con «contraseña incorrecta»).
- Status global Supabase: Operational — el fallo era **del proyecto**, no del proveedor entero.

---

## Causa raíz

**Bloqueo / suspensión del proyecto Supabase por falta de pago (facturación).**

No era un bug de código de rimec-web ni un fallo de autenticación de aplicación. El hostname del proyecto dejó de existir en DNS hasta reactivación.

### Cómo se resolvió (hecho Director 2026-08-03)

- Colaborador **Andrés** tenía **sesión GitHub abierta** en su casa.
- Desde esa sesión accedió al Dashboard / billing de Supabase.
- **Realizó el pago** que estaba bloqueando el proyecto.
- Tras el pago, DNS y API volvieron; smoke prod: `v_stock_rimec` ≈ **2274** filas · sitios HTTP 200.

### Ruido colateral (no fue la causa del DNS)

- Owner Héctor sin 2FA GitHub en teléfono nuevo → recuperación de cuenta GitHub (1–3 días) en paralelo.
- Códigos de recovery en PC parcialmente inválidos / lista posiblemente obsoleta.
- Confusión inicial con «error de autenticación» del día anterior (síntoma distinto: servidor existía vs proyecto ausente).

---

## Lección (holding)

1. **Un solo owner con GitHub 2FA frágil** = no poder Restore/pago en crisis.
2. **Facturación Supabase** tumba **todas** las apps a la vez (agua y aceite Sales Report vs pilares no aplica: ambas usan el mismo proyecto).
3. Síntoma UI (`fetch failed`) ≠ bug de filtros: primero probar **DNS del Project URL**.
4. Backup automático documentado no sustituye dump recuperable **antes** del incendio.
